# 自动化测试平台 技术方案

| 状态 | 草案 v0.1 |
| --- | --- |
| 日期 | 2026-10-16 |

## 1. 背景与目标

### 1.1 一句话定位

面向普通人的 Web UI 自动化测试平台：在内置浏览器里「点点点」即可录制用例，平台统一管理，一键回放，失败时有理有据。

### 1.2 核心用户故事

1. **录制**：打开应用，输入网址，正常操作页面，随手插入断言，得到一条结构化用例。
2. **管理**：项目 → 模块树 → 用例，步骤可视化编辑（增删改、排序），元素入元素库跨用例复用。
3. **复现**：一键回放；失败时给出步骤级结果与证据（每步截图、全程视频），明确哪一步、哪个元素、哪个断言、为什么失败。

### 1.3 本期明确不做

接口测试、移动端/桌面端被测对象、性能压测、定时调度、通知集成、演示视频与配音、AI 生成用例、定位器自愈。均列入远期路线图。

## 2. 名词解释

| 名词 | 含义 |
| --- | --- |
| 用例 | 一次完整的被测场景，由有序步骤组成 |
| 步骤 | 最小动作单元：动作 + 目标元素 + 参数，可附带断言 |
| 元素库 | 被测页面元素的集中登记处，带多候选定位器，跨用例复用 |
| 执行记录 | 一次回放产生的运行数据，与用例定义严格分离 |
| 证据 | 步骤粒度的截图、全程视频、错误信息等 |
| 受控浏览器 | 由平台创建并全程监听的浏览器实例（Electron 内置） |
| CDP | Chrome DevTools Protocol，控制/观测 Chromium 的标准协议 |
| 串流 | 将受控浏览器画面实时推送到网页并回传操作（远期） |

## 3. 竞品调研结论

调研覆盖 Selenium IDE、Playwright codegen、Cypress Studio、UI.Vision、Automa、Katalon、TestCafe Studio、Testim、mabl、Reflect、Ghost Inspector、TestSigma、MeterSphere、Sonic（2026-10）。

| 来源 | 机制 | 我们如何使用 |
| --- | --- | --- |
| Selenium IDE | `.side` 纯 JSON 工程、`targets` 多候选定位器 | 用例 JSON schema 的基础形态 |
| Katalon | 元素库（多候选定位器集中管理）、Manual/Script 双视图 | 元素库设计；表格视图优先的可视化编辑 |
| Playwright | 定位器生成算法：testId → role+名称 → text → css，生成时验证唯一性 | 录制期定位器生成器照此实现 |
| mabl | 证据链：每步截图 + 视频 + console + HAR | 失败报告证据结构的对标 |
| Reflect | 录制环境即执行环境，录像即证据 | 内置浏览器录制、零环境噪声 |
| Cypress Studio（Cypress 15 已移除） | 反例：录制直接往代码里插命令，不可管理 | 坚持结构化产物，不产裸代码 |

三条结论：

1. 用例 = 结构化 JSON（有序动作列表：动作 + 定位器 + 值 + 断言），行业收敛二十余年；Cypress Studio 的消亡反证了「裸代码产物」路线走不通。
2. 「Electron + 内置受控浏览器」在主流产品中没有成熟先例，是差异化空位；所需零件（CDP 三合一底座）已经验证可得。
3. 串流走 CDP screencast 桥即可，不引入 neko/WebRTC；视频用 Playwright recordVideo。

## 4. 总体设计

### 4.1 产品形态

MVP 单入口：**Electron 桌面应用**，窗口三栏布局。

- 左栏：项目 / 模块树 / 用例列表
- 中栏：内置受控浏览器——**录制的舞台**；顶部网址栏、设备预览（预设/横竖屏/缩放）与「开始录制 / 回放」控制条。回放默认通过本地 CDP 交给 Playwright 驱动受控视图（中栏可见地执行，步骤截图证据）；可切换独立 Chromium 窗口回放以录制全程视频
- 右栏：步骤面板（录制中实时追加，可编辑、排序、插断言）、元素库、报告

Web 管理台与网页端串流为二期入口；数据层与服务端同构，届时平滑迁移。

### 4.2 模块划分

- **UI 层**（renderer 进程）：管理面板、录制工具条、步骤编辑器、报告查看。
- **核心层**（main 进程）：
  - 浏览器控制：创建与导航受控浏览器（录制经 `executeJavaScript` 注入收集脚本捕获事件；CDP / `webContents.debugger` 预留给串流，M1 不附加）；
  - 录制引擎：注入脚本监听 DOM 事件 → 识别语义动作（click / fill / select / 按键）→ 定位器生成器产出候选 → 追加步骤；
  - 回放引擎：Playwright 读取用例 JSON，编译执行，auto-wait，逐步骤记录结果与证据；
  - 证据采集：步骤截图（Playwright screenshot）+ 全程视频（recordVideo）。
- **数据层**：SQLite，驱动用 Node 内置的 `node:sqlite`（Electron 内置运行时自带，零原生模块、零 rebuild），ORM 用 Drizzle；七表（projects / modules / cases / case_steps / elements / runs / run_steps），证据文件落本地目录，数据库存引用。

### 4.3 用例数据模型

原则：用例定义与执行记录分离；证据落到步骤粒度；元素集中登记、多候选定位器、断言为一等属性。

```json
{
  "case": {
    "id": "c-001",
    "name": "登录成功",
    "projectId": "p-001",
    "startUrl": "https://demo.example.com/login",
    "steps": [
      { "id": "s-001", "action": "fill", "elementId": "el-001", "params": { "value": "{{username}}" } },
      { "id": "s-002", "action": "click", "elementId": "el-003" },
      {
        "id": "s-003",
        "action": "assert",
        "elementId": "el-004",
        "assertion": { "type": "text", "expected": "登录成功" }
      }
    ]
  },
  "elements": {
    "el-003": {
      "name": "登录按钮",
      "locators": [
        { "type": "testId", "value": "login-submit" },
        { "type": "role", "value": "button", "name": "登录" },
        { "type": "css", "value": "#login-form button[type=submit]" }
      ]
    }
  }
}
```

回放时按候选顺序尝试定位，全部失败则该步骤失败，并记录实际页面状态作为证据。

步骤级结果（StepResult）字段：`status` / `durationMs` / `locatorHit`（命中的候选层级与定位器）/ `triedCandidates`（逐候选尝试记录）/ `assertion`（type 与 expected vs actual）/ `screenshotPath`。

## 5. 关键技术选型

| 领域 | 选型 | 理由 |
| --- | --- | --- |
| 桌面框架 | Electron | 单一形态承载管理 + 内置浏览器 + 录制；`webContents.debugger` 原生提供 CDP |
| 浏览器引擎 | Chromium（内置）+ Playwright（回放） | 录制与回放共用同一 CDP 协议栈 |
| 定位器生成 | 多候选链 testId → role+名称 → text → css | 借鉴 Playwright 算法，生成时验证唯一性 |
| 视频 | Playwright recordVideo（WebM） | 引擎原生；M1 报告页直接播 WebM，ffmpeg 转码在 backlog |
| 存储 | SQLite（`node:sqlite` + Drizzle ORM）+ 本地证据目录 | 零原生模块、零部署；schema 与未来服务端同构 |
| 前端 | React + Vite | 生态成熟 |
| UI 库 | HeroUI（Tailwind 系） | 组件即源码、可定制、观感现代；无 Tree 组件，模块树用 react-arborist 补足 |
| 状态管理 | TanStack Query + Zustand | 异步数据（IPC 封装）与 UI 态分离，不引入 Redux |
| 工程化 | pnpm + Turborepo、electron-vite、electron-builder + electron-updater、Vitest、Biome | 2026 社区共识组合；monorepo 分包原则见 4.2 |
| 语言 | TypeScript 全栈 | 与 Electron / Playwright 同生态 |

远期：网页端串流采用 CDP screencast + WebSocket 桥；如需多人观看再评估 neko（当前不引入）。

## 6. MVP 范围与里程碑

### 6.1 MVP 范围（做到即达标）

1. Electron 应用可安装、可运行；
2. 输入网址打开内置浏览器并录制：click / fill / select / 按键 / 断言（状态、文本、值、属性、样式、数量、页面级）/ 滚动 / 等待；支持设备预设与用例变量；
3. 用例管理：项目、模块树、用例、步骤增删改排序、元素库；
4. 一键回放，生成执行记录：步骤级结果（成功/失败/耗时）；
5. 证据：每步截图 + 全程视频；失败报告页有理有据。

### 6.2 验收场景（三幕剧）

1. 仓库自带一个测试 HTML 页面（登录表单）；
2. 在内置浏览器录制「登录成功」用例，回放通过；
3. 修改测试页面（改按钮文案、挪动元素、删除目标元素之一）后再次回放——用例失败，报告明确指出：失败的步骤序号、命中的候选定位器、断言类型与期望值/实际值对比，并附该步截图与全程视频。

### 6.3 里程碑

| 阶段 | 内容 |
| --- | --- |
| M1（MVP） | 6.1 全部 |
| M2 | Web 平台化：服务端 + 管理台 + 多人协作（数据层迁移） |
| M3 | 网页端串流远控受控浏览器 |
| M4 | 定时执行 / CI / 通知 / 多环境参数化 |
| 远期 | 演示视频+配音、定位器自愈、AI 生成用例 |

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 定位器质量（最大风险） | 多候选链 + 录制时唯一性验证 + 元素库集中修复（改一处、全用例生效）；自愈列远期 |
| 事件识别边界（拖拽、弹窗） | MVP 仅支持基础动作集；iframe 已支持（preload 进入子 frame + 逐 frame 注入采集器）；其余边界场景记入 backlog |
| CDP 串流丢帧、无原生光标 | 远期项：自绘光标、screencastFrameAck 背压控制 |
| 双线工程量失控 | MVP 只做 Electron 单线，服务端仅保留同构 schema |
| 数据模型早期设计不当导致返工 | schema 先行评审，用例/执行记录/元素严格分离 |
