# 自动化测试平台演进方案

> 定位：从「单机录制回放工具」演进为「团队可用的企业级 Web 自动化测试平台」。
> 本文回答三个问题：现在有什么、还要做什么、具体怎么做。
> 版本：v1 · 2026-10-17

---

## 0. 结论先行

- **产品目标**：让不会写代码的测试同学能录制、让会写代码的同学能扩展、让团队能按计划批量跑、让失败能定位、让结果能进研发流程。
- **三条主线**：
  1. **平台化**：服务端 + Web 管理台 + 执行 Worker + 桌面录制器，多用户、多项目、多环境。
  2. **覆盖深度**：录制与断言覆盖企业 Web 开发的主流场景（iframe/微前端、弹窗多标签、复杂控件、网络与视觉断言）。
  3. **工程闭环**：测试计划 → 批量/定时执行 → 报告/趋势 → 通知 → CI 接入。
- **建议节奏**：M2 平台底座与批量执行 → M3 环境/密钥/调度/通知 + 录制深度 → M4 断言与证据深度 → M5 规模化与协作 → M6 智能化与生态。

## 1. 现状盘点

### 1.1 已具备（M1）

| 域 | 能力 |
|---|---|
| 录制 | 点击 / 输入 / 下拉 / 按键 / 滚动 / 拖拽（含滑块验证码）/ 断言拾取；同域与跨域 iframe 采集；实时步骤面板、录制诊断、停止后保留草稿 |
| 定位 | 候选链 `testId → role+名称 → text → CSS`，逐层回退并记录命中层级 |
| 用例 | 项目 / 模块 / 用例树；步骤拖拽排序、复制、内联编辑；⌘S 保存；元素库（改名、删候选） |
| 断言 | 元素状态 8 类、数量、文本 3 类、值 2 类、属性、CSS、页面级 URL/标题/页面文本；超时轮询与 expected/actual |
| 参数化 | 用例变量 `${VAR}`、步骤条件（不满足跳过） |
| 回放 | 双模式：中栏 CDP 嵌入（步骤截图）/ 独立窗口（全程视频）；进度与停止；失败即停 + 逐候选归因 |
| 设备 | Desktop / Laptop / Tablet / iPhone / Android 预设，横竖屏与缩放 |
| 证据 | 步骤截图、独立窗口视频、执行记录、报告页 |
| 工程 | CLI 单用例回放（`--url/--headless` + 退出码）、E2E、单元测试、明暗主题、Toast/确认框 |
| 存储 | Electron + SQLite 本地单机 |

### 1.2 关键缺口

| 缺口 | 影响 | 优先级 |
|---|---|---|
| **iframe 回放缺少 frame 上下文** | 录制能进 iframe，但元素定位器没有记录所属 frame，回放时在主文档查找会失败 | P0 |
| 无服务端 / 多用户 / 权限 | 无法团队共享、并发使用、审计 | P0 |
| 无测试计划 / 套件 / 批量执行 | 只能一条条跑，无法做回归集 | P0 |
| 无重试 / 超时策略 / 软断言 | 环境抖动造成误报，失败即停不利于收集全貌 | P0 |
| 无环境与密钥管理 | 多环境地址、账号密码硬编码在用例里 | P0 |
| 无定时 / 通知 / CI 批量 | 无法接入研发流程 | P0 |
| 弹窗 / 多标签、hover / 双击 / 右键、文件上传下载 | 企业系统常见交互无法录制 | P1 |
| 网络 / API / 控制台 / 视觉 / 可访问性断言 | 只能断言「看得见的东西」 | P1 |
| 数据驱动 / 循环 / setup-teardown | 无法参数化跑多组数据、无法准备/清理测试数据 | P1 |
| 无 Trace / 网络日志 | 失败定位仍依赖截图 | P1 |
| 跨浏览器 / 并行 / 分布式 | 只能 Chromium、串行执行 | P2 |
| 用例版本 / 评审 / 导入导出 / Git 同步 | 资产治理不足 | P2 |
| 定位器自愈 / AI 生成与归因 | 维护成本高 | P3 |

### 1.3 现有架构的优点与约束

**优点**

- 用例是结构化 JSON，与执行记录严格分离，天然适合服务端化。
- `packages/recorder` 与 `packages/runner` 零 Electron 依赖，可直接被 Worker 复用。
- 多候选定位器 + 步骤级证据 + 失败归因，已经是「可诊断」的底座。
- CDP + Playwright 双栈，录制、嵌入回放、独立回放共用一套执行引擎。

**约束**

- 桌面端单机 SQLite，无法多人共享。
- 受控视图是 Electron 原生 `WebContentsView`，Web 端录制需要新的承载形态（桌面录制器或浏览器扩展）。
- 打包版加载 `file://` 有限制，企业使用应以 http(s) 为主。

## 2. 目标与成功标准

### 2.1 产品目标

1. **低门槛录制**：业务/测试同学不写代码即可产出可回放用例。
2. **可维护资产**：元素库、变量、环境、版本、批量操作，避免复制粘贴。
3. **可靠的执行**：可并行、可重试、可定时、可取消，结果稳定可解释。
4. **闭环的反馈**：报告 → 趋势 → 通知 → CI，失败能快速定位到步骤与候选。
5. **企业级治理**：多项目、多角色、密钥安全、审计、数据保留。

### 2.2 用户与角色

| 角色 | 主要诉求 |
|---|---|
| 测试工程师 | 录制/编辑用例、维护元素库、跑回归、看失败原因 |
| 开发工程师 | 本地/CI 回放、看 Trace、修定位器 |
| 测试负责人 | 测试计划、覆盖率、质量趋势、失败分派 |
| 管理员 | 用户/权限、环境与密钥、执行资源、审计 |
| 业务同学 | 提交验收用例、查看结果（只读） |

### 2.3 场景矩阵（企业软件开发全覆盖目标）

| 场景 | 现状 | 目标阶段 |

                               │ HTTPS / SSE
┌──────────────────────────────▼──────────────────────────────────┐
│                        API 服务（NestJS）                        │
│  Auth/RBAC · 项目用例 · 计划调度 · 执行 API · 报告 · 通知 · 审计   │
└───────┬──────────────────────┬──────────────────────┬───────────┘
        │                      │                      │
┌───────▼────────┐   ┌─────────▼─────────┐   ┌────────▼──────────┐
│ PostgreSQL     │   │ Redis + BullMQ    │   │ S3 / MinIO        │
│ 元数据/结果     │   │ 执行队列/定时/重试 │   │ 截图/视频/Trace    │
└────────────────┘   └─────────┬─────────┘   └───────────────────┘
                               │ 消费任务
                 ┌─────────────▼─────────────┐
                 │     Runner Worker 池       │
                 │ Playwright + @atp/runner   │
                 │ 容器隔离 / 并发 / 超时      │
                 └─────────────┬─────────────┘
                               │ 执行结果 / 证据
                 ┌─────────────▼─────────────┐
                 │  通知通道（飞书/企微/邮件） │
                 └───────────────────────────┘

┌──────────────────────────────┐
│ 桌面录制器（Electron，可选）   │  录制高保真；通过 API 上传用例

### 3.2 部署拓扑

| 形态 | 适用 | 组成 |
|---|---|---|
| 单机 Compose | 内部小团队 / 试点 | api + web + postgres + redis + minio + 1~2 worker |
| 集群 | 多团队 / 大规模 | api 多副本 + worker 弹性伸缩 + 托管 PG/Redis/对象存储 |
| 桌面独立模式 | 离线 / 个人调试 | 保留现有 Electron + SQLite，可导出用例到平台 |

### 3.3 技术选型（建议）

| 层 | 选型 | 理由 |
|---|---|---|
| API | Node.js + TypeScript + NestJS | 与 `packages/*` 同语言；模块化、DI、OpenAPI、RBAC 生态成熟 |
| ORM | Drizzle | 与现有代码一致，迁移可控 |
| 数据库 | PostgreSQL | 并发、索引、JSONB、审计与报表都能承载 |
| 队列 | Redis + BullMQ | 延迟任务、重试、并发、定时；与 Node 生态契合 |
| 对象存储 | S3 / MinIO | 截图/视频/Trace 容量大，签名 URL 读取 |
| Web | React + Vite + HeroUI | 复用现有设计 token 与组件 |
| 实时 | SSE | 执行进度单向推送，比 WebSocket 简单稳定 |
| 认证 | OIDC（飞书 / Keycloak / Authing） | 企业 SSO、统一身份 |
| 密钥 | 服务端 KMS/Vault；桌面端 OS Keychain | 不明文落库 |
| Worker | Node + Playwright + `@atp/runner` | 复用执行引擎；容器隔离 |
| 可观测 | OpenTelemetry + Prometheus + Loki | 执行耗时、失败率、Worker 健康度 |
| 部署 | Docker / Docker Compose / K8s | 内部交付与弹性扩容 |

### 3.4 目标仓库结构

```
apps/
  server/        # NestJS API + 调度 + 通知 + 审计

  worker/        # 执行 Worker（Playwright）

  recorder/      # 采集器（页面脚本）

  shared/        # 通用工具、错误码、变量解析

```

### 3.5 核心数据流

```
录制（桌面） → 用例 JSON（含元素候选、变量、条件）
      │
      ▼
测试计划（选择用例/环境/并发/重试） → 调度（手动/定时/CI）
      │
      ▼
队列任务（run + case + env 快照） → Worker 执行
      │
      ├── 步骤结果 / 断言 expected-actual / 命中候选
      ├── 截图 / 视频 / Trace → 对象存储

```

### 4.2 关键设计

- **执行快照**：`runs` 创建时固化用例版本、环境变量、密钥引用；后续编辑用例不影响历史结果。
- **元素与 frame**：`elements.frame_path` 记录从主文档到目标 frame 的路径（frame 序号或 URL 模式），回放时先定位 frame 再定位元素。
- **变量作用域**：全局 < 项目 < 环境 < 计划 < 用例；同名后者覆盖前者。`${VAR}` 在执行时解析。
- **密钥引用**：用例只保存 `${secret.NAME}` 引用，真实值在执行时注入，日志与报告中脱敏。
- **保留策略**：截图默认 30 天、视频 14 天、Trace 7 天，可按项目配置；数据库保留执行摘要。

### 4.3 版本与审计

- 用例「保存草稿 → 发布版本」；执行只能引用已发布版本（或测试计划可配置草稿）。
- 所有写操作记录 `audit_logs`：谁、何时、改了什么、来源 IP。
- 支持导出/导入 JSON，用于 Git 备份与跨环境迁移。

## 5. 功能域设计

### 5.1 用例资产与测试计划

**目标**：从「单条用例」升级为「可管理的回归资产」。

- 测试套件（suite）：按功能域/回归范围组织用例；支持拖拽排序、批量加入。
- 测试计划（plan）：套件 + 环境 + 并发/重试/超时策略 + 通知策略。
- 标签与优先级：`smoke` / `regression` / `P0`；计划可按标签筛选。
- 批量操作：批量移动、复制、删除、加标签、启停。
- 用例版本：发布/回滚；执行记录关联版本。
- 搜索：名称、标签、元素、步骤文本、最近失败。
- 导入导出：平台 JSON、Postman/OpenAPI（API 用例）、JUnit 结果。

**验收**

- 能在 3 分钟内从 500 条用例中筛出「P0 + 登录模块」组成计划。
- 计划执行失败后可一键重跑失败用例。

### 5.2 录制与编辑

**目标**：覆盖企业 Web 的常见交互，录制产出可维护。

- **iframe/微前端**：录制时记录 frame 路径；元素库展示所属 frame；回放按 frame 定位（M2）。
- **多标签/弹窗**：录制 `open_tab/switch_tab/close_tab`；窗口句柄映射；回放时按 URL 或序号切换。
- **交互补齐**：hover、双击、右键、键盘组合键、文件上传/下载、滚动容器、日期控件。
- **网络感知**：录制关键 XHR/fetch（方法、URL、状态、响应摘要）；支持「等待某个请求完成」。
- **智能等待**：元素可见/可点击、网络空闲、请求匹配；避免固定 sleep。
- **编辑体验**：步骤分组、注释、拖拽排序、复制、禁用、批量编辑定位器、步骤搜索。
- **断点调试**：单步执行、从某步开始、失败暂停，便于维护。
- **多端录制**：桌面录制器（主）；浏览器扩展（可选，轻量）；Web 端远程录制（screencast，后期）。

**验收**

- 一个含 iframe、弹窗、文件上传、hover 的典型企业页面可完整录制并回放。
- 元素定位器支持按 frame 隔离，回放失败时报告指出 frame 与候选。

### 5.3 断言体系

**目标**：不仅断言「页面显示」，还能断言「系统行为」。

| 类别 | 内容 |
|---|---|
| 元素 | 可见/隐藏、存在/不存在、启用/禁用、勾选、数量、文本、值、属性、CSS |
| 页面 | URL、标题、页面文本、滚动位置 |
| 网络 | 请求发生、状态码、响应体 JSONPath、响应时间、请求头 |
| 控制台 | 无 error、指定日志出现 |
| 视觉 | 元素/整页截图基线对比（像素差/阈值） |
| 可访问性 | axe 规则集、严重级别 |
| 性能 | 首屏/接口耗时预算、资源大小 |
| 软断言 | 失败不中断，汇总报告 |
| 自定义 | JS 表达式断言（受控沙箱） |

**做法**

- 断言统一为 `{type, target, expected, timeout, soft}`，执行器按类型分派。
- 网络断言依赖录制期/回放期的 CDP Network 事件收集。
- 视觉基线存对象存储，支持「接受新基线」与差异图。
- 软断言收集失败但继续执行，最终汇总。

**验收**

- 一条用例可同时断言 UI 文本、接口 200、控制台无 error；失败报告能分别列出。

### 5.4 执行引擎

**目标**：稳定、可扩展、可解释。

- Worker 池：容器化 Playwright；按项目/浏览器打标签；心跳与并发上限。
- 队列：BullMQ；任务包含用例/环境/密钥引用/重试策略；支持优先级与取消。
- 并行与分片：计划级并发、用例级并行、按分片下发；同一账号数据隔离策略。
- 重试：步骤级/用例级；仅对可重试错误（超时、网络）生效；记录重试次数。
- 超时：用例总时长、单步超时、断言超时。
- 失败策略：失败即停 / 继续执行 / 软断言。
- 浏览器：Chromium（默认）→ Firefox/WebKit（M5）；设备模拟与真机接入（后期）。
- 证据：截图、视频、Trace、网络 HAR、控制台日志；对象存储 + 签名 URL。
- 实时：SSE 推送步骤进度；支持取消与重跑。
- 隔离：每个 run 独立浏览器上下文；登录态通过 storageState 复用。

**验收**

- 100 条用例、3 个 Worker 并行执行，租户级资源隔离，失败任务可重试且证据完整。

### 5.5 环境、数据与密钥

**目标**：同一套用例在多环境稳定运行。

- 环境：名称、baseUrl、浏览器/视口、默认超时、变量集合。
- 变量作用域：全局/项目/环境/计划/用例；支持 `secret.` 前缀。
- 密钥：AES-GCM 加密存储（服务端 KMS/Vault）；桌面端 OS Keychain；日志/报告脱敏。
- 登录态：支持「登录一次，复用 storageState」；API 登录获取 token；MFA 人工暂停。
- 测试数据：
  - setup/teardown 步骤（API 或 UI）。
  - 数据集：CSV/JSON，驱动用例循环执行。
  - 数据工厂：调用 API 创建/清理数据，记录清理步骤。
- 环境切换：计划执行时选择环境；用例中不写死地址与账号。

**验收**

- 同一用例在 dev/staging/prod 三套环境切换执行，无需修改用例。
- 密钥不出现在用例 JSON、日志、报告中。

### 5.6 CI/CD 与调度

**目标**：让平台成为研发流程的一部分。

- CLI：`atp run --plan <id> --env <env> --report junit.xml`；退出码；JSON 输出。
- Docker 镜像：api/worker/web 一键部署；Worker 镜像内置 Playwright 浏览器。
- 流水线：GitHub Actions / GitLab CI / Jenkins 示例；PR 触发 smoke，合并触发 regression。
- Webhook：执行开始/完成/失败事件；签名校验。
- 定时：cron + 时区；错峰；失败重试；并发限制。
- 通知：飞书/企微/Slack/邮件；按计划/项目配置；失败摘要 + 报告链接；恢复通知。
- 报告导出：JUnit XML、HTML、JSON；对接质量平台。

**验收**

- PR 提交触发 smoke 计划，结果回写 PR 检查；失败消息推送到飞书群并附报告链接。

### 5.7 报告与分析

**目标**：失败能定位，质量能趋势化。

- 实时执行视图：计划/用例/步骤进度、当前截图。
- 报告详情：步骤、耗时、候选命中、断言 expected/actual、截图、视频、Trace、网络、控制台。
- 趋势：通过率、执行时长、失败 Top N、flaky 用例、环境对比。
- Flaky 识别：同一用例多次执行结果不一致；自动标记与隔离建议。
- 失败分派：责任人、评论、状态（待修/已修/忽略）。
- 导出：JUnit/HTML；分享只读链接（带有效期）。

**验收**

- 失败报告能在 30 秒内回答：哪一步、哪个元素、哪层候选、期望/实际、截图/Trace 在哪。

### 5.8 协作与治理

- 组织/项目/角色：owner/admin/editor/viewer；项目级权限。
- SSO：OIDC；SCIM（后期）。
- 审计：登录、用例变更、执行、密钥访问、权限变更。
- 评论与 @：用例/执行报告上讨论。
- 评审：用例发布前审批（可选）。
- 数据保留与合规：按项目配置证据保留；导出/删除个人数据。

### 5.9 平台运维

- 备份：PostgreSQL 每日备份；对象存储生命周期。
- 监控：API/Worker/队列/存储健康度；执行失败率与 P95 时长。
- 升级：数据库迁移版本化；Worker 滚动升级；桌面端自动更新。
- 容量：Worker 并发与浏览器内存估算；队列积压告警。

## 7. 关键技术专题

### 7.1 iframe / Shadow DOM / 多标签的定位与回放

- **iframe**：元素的 locator 增加 `framePath`（从主文档到目标 frame 的索引链，例如 `[0, 2]`）；回放时 `page.frames()` 解析后在该 frame 内定位。跨域 frame 同样适用。
- **Shadow DOM**：Playwright 的 CSS 定位默认穿透 open shadow root；closed shadow root 需要录制期建立映射（优先 role/text）。
- **多标签**：执行上下文维护 `page` 映射；动作 `open_tab/switch_tab` 记录 URL/序号；回放按 URL 或序号切换，并做超时兜底。
- **弹窗**：与多标签同一套 page 管理；关闭后回到上一个 page。

### 7.2 执行隔离与并行

- 每个 run 独立 `BrowserContext`；登录态用 `storageState`。
- 同一账号的并行任务需数据隔离策略（不同租户/不同测试账号/串行队列）。
- Worker 容器限制 CPU/内存；Playwright 浏览器预装。
- 队列任务幂等：runId 唯一；重复消费不重复落库。
- 取消：Worker 收到取消信号后关闭 context，标记 cancelled。

### 7.3 证据与对象存储

- 存储键：`org/project/run/step.png`；生命周期按类型配置。
- 上传走 Worker → 对象存储（预签名 PUT）；API 返回签名 GET。
- 报告页懒加载大文件；Trace 用官方 viewer 嵌入。
- 数据库只存元数据与摘要，避免膨胀。

### 7.4 密钥与合规

- 服务端：Vault/KMS 加密；密钥只在 Worker 内存中解密；日志脱敏。
- 桌面端：macOS Keychain / Windows Credential Manager。
- 审计：密钥读取、修改、执行引用都记录。
- 报告/导出默认脱敏，支持「显示敏感值」需权限。

### 7.5 录制的多端形态

| 形态 | 适用 | 取舍 |
|---|---|---|
| 桌面录制器（现有） | 高保真录制、复杂 iframe/弹窗 | 需安装；跨平台打包 |
| 浏览器扩展 | 轻量、随时录制 | iframe/弹窗能力受限；需维护扩展 |
| Web 远程录制 | 团队共享、无需安装 | CDP screencast + 远程输入；实现复杂 |

建议：M2–M4 以桌面录制器为主；浏览器扩展作为 P2 补充；Web 远程录制在 M5 评估。

### 7.6 从桌面到服务的迁移

- 保留本地模式，提供「导出用例包」→ 服务端「导入」。
- 领域模型与 `packages/model` 共用；API 契约从 IPC 迁移为 HTTP（zod schema 复用）。
- 先双写/双读一段时间，确认无回归后切换默认入口。
- 桌面端后续定位为「录制器 + 本地调试」，服务端为团队主入口。

## 10. 风险与开放问题

| 风险 | 影响 | 缓解 |
|---|---|---|
| 平台化改造范围大 | 交付周期长 | M2 先做「服务端 + 用例 + 批量执行」最小闭环 |

| 并行导致数据冲突 | 结果不稳定 | 账号/数据隔离策略；同账号串行 |
| 密钥安全 | 合规风险 | Vault/KMS + 脱敏 + 审计 |
| Worker 资源成本 | 扩容成本 | 容器化 + 自动缩容 + 分片 |
| 视觉回归误报 | 维护成本 | 阈值/遮罩/基线审批 |
| 跨浏览器差异 | 用例维护 | 分浏览器基线；标签化执行 |
| 用户不愿迁移 | 推广失败 | 保留本地模式 + 一键导入 + 试点团队 |

**开放问题**

1. 首个落地团队与项目是哪一个？优先覆盖哪些业务场景？
2. 服务端部署在何处（内网 K8s / 单机 Compose / 云）？
3. 身份体系用飞书 SSO 还是独立账号？
4. 证据存储是否已有 S3/MinIO，保留周期要求？
5. 是否需要对接现有缺陷系统（Jira/飞书任务）？
