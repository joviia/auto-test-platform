# 本地优先的功能演进方案

> 边界：**技术栈不变、单机本地、不做服务端、不做多用户/云**。
> 目标：先把本地功能做完整，覆盖软件工程对测试的基本要求；云化以后再说。
> 版本：v2 · 2026-10-17

---

## 0. 结论先行

- **现在的问题不是架构，是功能覆盖太窄**：一次只能跑一条用例、录制动作少、断言薄、没有测试计划/套件、没有数据与环境管理。
- **下一步主线**：把「单条用例录制回放」升级为「本地可执行的测试工程闭环」。
- **优先级**：
  1. 测试执行闭环（套件/计划/批量/重试/报告）——最缺
  2. 场景覆盖（弹窗多标签、hover/双击/右键、上传下载、复杂控件）
  3. 断言与证据（网络/控制台/软断言/Trace）
  4. 数据与环境（变量作用域、环境、密钥、数据集、setup/teardown）
  5. 维护与度量（全局元素库、版本、趋势、flaky）
- **技术栈不变**：Electron + WebContentsView + CDP + Playwright + SQLite。

## 0.1 交付原则（所有里程碑通用）

这一节是约束，不是建议。每个阶段都必须满足，否则不算完成。

### 1. 目标导向，先定义「可感知的结果」

每个里程碑开工前先写清楚四句话：

- **谁**用（测试同学 / 开发 / 负责人）
- **在什么场景**用
- **之前做不到什么**
- **之后能做到什么**（用户能亲眼看到、亲手操作）

写不出这四句话，就不开工。

### 2. 每个阶段必须有「锚定交付物」

- 一个可演示的**用户旅程（Demo Script）**
- 一组用户能看到的**界面/交互/报告变化**
- 一份可复现的**验收步骤**

不能出现「功能做了但用户察觉不到」的情况。纯内部重构必须搭在一个用户可感知的交付物里一起交付。

### 3. 垂直切片，前后端一起交付

在本项目里，「前后端」指整条链路：

```
Renderer（UI/交互）
  ↕ IPC
Main（服务/调度/DB/证据）
  ↕
Runner（回放引擎/断言/证据）
  ↕
SQLite（数据/记录）
  ↕
CLI（如适用，CI 入口）
```

一个功能必须同时具备：**入口 + 操作 + 数据落库 + 执行/回放 + 结果展示 + 空/错/加载态**。禁止只交主进程能力、只交 UI 壳子、或只交引擎而没有入口。

### 4. 与现有功能形成联动

新功能不能是孤岛。交付时必须回答：

- 入口放在现有信息架构的哪里？是否复用现有导航/面板？
- 和用例树、步骤编辑器、元素库、报告、执行记录怎么联动？
- 空状态、加载态、失败态、禁用态怎么表现？
- 运行中/完成后，AppBar、状态栏、右栏、报告是否同步？

### 5. UI/UX 与现有产品一致

- 复用现有设计 token、间距、字号、颜色、明暗主题。
- 复用现有交互模式（侧栏、分段标签、卡片、Toast、确认框、空状态）。
- 新页面必须过一遍：空态 / 加载 / 错误 / 禁用 / 键盘焦点 / 暗色模式。
- 文案统一、动作可预期，不让用户猜。

### 6. 完成定义（DoD）

- [ ] 用户旅程可完整演示（从头到尾，无手工改库）
- [ ] 全链路改动完成（UI + 主进程 + DB + Runner + CLI/报告）
- [ ] 与现有功能联动，无孤立入口
- [ ] 空/加载/错误/禁用/暗色模式走查
- [ ] E2E 或集成测试覆盖主路径
- [ ] 文档（使用说明 + 限制）更新

### 7. 反例清单（出现即打回）

- 只做了引擎/IPC，界面上看不到
- 新增一个页面，但和现有导航、报告、执行记录不打通
- 功能只能走「正常路径」，没有空态/错误态
- 新界面风格与现有产品不一致
- 交付后用户说不出「哪里变了」
- 只做前端 mock，数据没有真正落库/回放

## 1. 现状盘点

### 1.1 已具备

| 域 | 能力 |
|---|---|
| 录制 | 点击 / 输入 / 下拉 / 按键 / 滚动 / 拖拽（含滑块）/ 断言拾取；同域与跨域 iframe 采集 |
| 定位 | testId → role+名称 → text → CSS 多候选链；逐层回退与命中记录 |
| 用例 | 项目 / 模块 / 用例树；步骤拖拽排序、复制、内联编辑；⌘S |
| 断言 | 元素状态 8 类、数量、文本 3 类、值 2 类、属性、CSS、页面级 URL/标题/页面文本 |
| 参数化 | 用例变量 `${VAR}`、步骤条件（跳过） |
| 回放 | 中栏 CDP 嵌入（截图）/ 独立窗口（视频）；进度与停止；失败即停 + 候选归因 |
| 设备 | Desktop / Laptop / Tablet / iPhone / Android，横竖屏与缩放 |
| 证据 | 步骤截图、独立窗口视频、执行记录、报告页 |
| 工程 | CLI 单用例回放、E2E、单测、明暗主题、Toast/确认框 |

### 1.2 关键缺口（按影响排序）

| 缺口 | 影响 |
|---|---|
| **iframe 回放没有 frame 上下文** | 录制能进 iframe，回放时在主文档找元素会失败 |
| 只能单条用例执行 | 没有套件/计划/批量，做不了回归 |
| 动作覆盖窄 | 弹窗/多标签、hover、双击、右键、上传/下载、组合键、复杂控件都录不了 |
| 断言薄 | 没有网络、控制台、视觉、可访问性、性能断言；没有软断言 |
| 没有测试数据/环境 | 地址与账号写死在用例里；没有数据集、setup/teardown |
| 没有测试资产治理 | 元素库只能看当前用例；没有版本、导入导出、批量操作 |
| 没有度量 | 只有执行列表，没有趋势、flaky、失败分派 |
| CI 能力弱 | CLI 只能跑单条 case JSON，没有批量与 JUnit |

### 1.3 现有架构的优点（保持不变）

- 用例是结构化 JSON，适合本地演进，也天然兼容未来的云化。
- `packages/recorder` / `packages/runner` 零 Electron 依赖，CLI 可以直接复用。
- 多候选定位器 + 步骤级证据 + 失败归因，已经是可诊断的底座。
- 技术栈不需要调整：本地 SQLite 足够支撑测试计划、环境、执行记录与趋势。

| 测试工程实践 | 本地平台需要什么 | 现状 |
|---|---|---|

| 测试设计（Test Design） | 用例步骤、预期结果、前置条件、数据 | ⚠️ 步骤/断言有，前置/数据缺 |
| 测试环境（Environment） | 多环境地址、变量覆盖、浏览器/视口 | ❌ |
| 测试数据（Test Data） | 数据集、变量作用域、setup/teardown、清理 | ⚠️ 只有用例变量 |
| 测试执行（Execution） | 批量、重试、超时、失败策略、取消 | ❌ 单条串行 |
| 缺陷管理（Defect） | 失败归因、责任人、外部系统链接 | ⚠️ 只有报告 |
| 测试报告与度量 | 通过率、耗时、趋势、flaky、对比 | ⚠️ 只有单次记录 |
| 回归与持续测试 | 套件回归、CLI/CI、JUnit、退出码 | ⚠️ 单条 CLI |
| 可追溯性 | 用例 ↔ 需求/缺陷/计划的关联 | ❌ |
| 可维护性 | 全局元素库、版本、导入导出、定位器健康 | ⚠️ 部分 |

> 结论：本地化完全可以把这张表补齐，不需要服务端。

## 4. 功能域与做法

### 4.1 测试执行闭环（L1，最优先）

**目标**：从「单条用例」升级为「套件 → 计划 → 批量执行 → 报告」。

- **套件（Suite）**：按功能域/模块组织用例，支持拖拽排序与批量加入。
- **测试计划（Plan）**：套件 + 执行策略（重试次数、超时、失败继续/即停）+ 环境（L4 前可先只用默认环境）。
- **本地批量执行**：主进程顺序执行计划内用例；每条用例独立上下文；实时进度；可取消。
- **重试与超时**：用例级重试（默认 0，可配 1~3）；单步/用例超时；重试记录独立保存。
- **失败策略**：失败即停 / 继续执行（收集全貌）；报告标注。
- **执行记录**：run 关联 plan/suite/case；保留每次尝试。
- **CLI 批量**：`atp run --plan <id> [--junit report.xml] [--headless]`；退出码；可被 CI 调用。
- **JUnit XML**：每条用例一个 testcase，失败附步骤与断言信息。
- **标签/优先级**：`smoke` / `regression` / `P0~P2`；计划可按标签筛选。
- **iframe 回放修复**：元素记录 frame 路径，回放先定位 frame。

**怎么做**

- SQLite 新增：`suites`、`suite_items`、`plans`、`plan_items`、`plan_runs`（或复用 runs 增加 plan_id）。
- 批量执行器：复用 `runCaseOnPage`，在本地起多个 Playwright 浏览器（先串行，L5 再并行）。
- CLI 读取本地 DB 的计划（只读），避免依赖桌面 UI。
- 重试：包一层 `runCaseOnPage`，失败后按策略重跑并记录 attempt。
- JUnit：新增 `packages/runner/src/junit.ts`，纯函数便于测试。

**验收**

- 一个 50 条用例的计划可一键执行，失败用例可重跑。
- 执行结束生成 JUnit，CI 可直接消费。
- iframe 用例回放通过。

### 4.2 录制与动作（L2）

**目标**：覆盖企业 Web 常见交互。

- 弹窗/新标签：录制 `open_tab / switch_tab / close_tab`；受控视图允许 `window.open` 并注入采集器。
- hover、双击、右键：新增动作；采集对应 DOM 事件。
- 键盘组合键：录制 `ctrl/meta/alt/shift + key`，回放用 `keyboard.press`。
- 文件上传：记录文件输入；本机测试数据目录保存文件路径，回放 `setInputFiles`。
- 文件下载：监听下载事件，证据落盘；断言文件存在/大小。
- 滚动容器：不仅窗口滚动，也支持可滚动元素。
- 复杂控件：日期选择器、富文本、下拉树、穿梭框——按「录制动作 + 组件策略」扩展，不引入组件库耦合。
- Shadow DOM：open shadow root 优先 role/text；closed 需录制期建立映射或手动修正。
- 元素库全局管理：跨用例搜索、合并、引用影响分析。

**验收**

- 一个含弹窗、上传、hover、右键的页面可完整录制并回放。
- 元素库能看出某元素被哪些用例引用。

### 4.3 断言与证据（L3）

**目标**：从「页面可见」扩展到「系统行为」。

| 类别 | 内容 |
|---|---|
| 网络 | 请求发生、状态码、响应体 JSONPath、响应时间 |
| 控制台 | 无 error、指定日志出现 |
| 软断言 | 失败不中断，汇总展示 |
| 视觉（L5） | 元素/整页截图基线对比、差异图、阈值 |
| 可访问性（L5） | axe 规则集与严重级别 |
| 性能（L5） | 首屏/接口耗时预算 |

**证据**

- Playwright Trace（失败用例默认开启，成功可选）。
- HAR / 网络日志、控制台日志。
- 嵌入回放可选视频（后续用 CDP screencast，不依赖 ffmpeg）。
- 报告页可直接打开 Trace、查看网络与控制台。

**怎么做**

- 网络：执行期监听 `page.on('request/response')`，断言按轮询匹配。
- 控制台：监听 `console` 与 `pageerror`。
- 软断言：步骤结果增加 `softFailed`，继续执行，最终汇总。
- Trace：`context.tracing.start/stop`，文件落证据目录。
- 视觉：截图 + `pixelmatch`（本地计算），基线存本地目录。

**验收**

- 一条用例可同时断言 UI 文本、接口 200、控制台无 error；失败报告分别列出。
- 失败用例报告可直接打开 Trace。

### 4.4 数据、环境与密钥（L4）

**目标**：同一套用例在不同环境/数据下运行。

- **环境（Environment）**：名称、baseUrl、浏览器/视口、默认超时、变量集合。
- **变量作用域**：全局 < 项目 < 环境 < 计划 < 用例；同名覆盖。
- **密钥**：Electron `safeStorage`（macOS Keychain / Windows Credential Manager）加密；日志与报告脱敏。
- **数据集**：CSV/JSON 导入；用例循环执行，结果按数据集聚合。
- **setup / teardown**：前置/后置步骤（UI 或 HTTP）；失败不执行后置时给出提示。
- **HTTP 动作**：为数据准备/清理、API 断言、混合测试提供基础。
- **登录态复用**：Playwright `storageState` 保存与复用。

**验收**

- 同一用例切换 dev/staging 两套环境无需修改。
- 20 组数据集一次执行，报告分组展示。
- 密钥不出现在用例 JSON、日志、报告中。

### 4.5 报告与度量（L5）

- 趋势：通过率、耗时、失败 Top N、环境对比。
- Flaky 识别：同一用例多次执行结果不一致，自动标记。
- 运行对比：两次执行的步骤级差异。
- 失败分派：责任人、备注、状态（待修/已修/忽略）。
- 分享：导出 HTML/JUnit；本地报告文件可直接发人。

### 4.6 CI 与定时（L5）

- CLI 批量与 JUnit（L1 已有基础）。
- 退出码、日志、artifacts 目录约定。
- GitHub Actions / GitLab CI 示例。
- 定时：优先使用系统 cron/launchd 调 CLI；应用内定时可作为辅助（应用需常开）。
- 通知：本地 Webhook / 飞书机器人（失败摘要 + 报告路径）。

### 4.7 可维护性与资产治理（L5）

- 用例版本：保存快照，可回滚；执行记录关联版本。
- 导入/导出：平台 JSON 包（用例 + 元素 + 变量 + 数据集）。
- 定位器健康度：统计候选命中层级；长期命中低层的元素给出修复建议。
- 全局元素库：合并重复元素、批量修复定位器。

### L1 · 测试执行闭环（M）

**谁 / 场景 / 之前 / 之后**

- 测试同学，在本地做回归；之前只能一条一条跑用例，之后可以建套件、建计划、批量跑、失败重跑、导出 JUnit。

**体验脚本**

1. 左树多选用例 → 右键/工具栏「加入套件」→ 新建套件「登录回归」。
2. 顶部导航出现「测试计划」→ 新建计划，选套件，设置重试 1 次、失败继续。
3. 点「执行计划」→ 右栏出现计划执行面板：`3/10 用例`、当前用例、步骤进度、通过/失败计数、重试标记。
4. 执行结束自动进入「报告」的计划视图：每条用例的状态、重试次数、失败步骤、截图。
5. 计划详情提供 CLI 命令与「导出 JUnit」。

**锚定交付物**

- 新的「测试计划」导航与页面（套件/计划列表、编辑、执行）。
- 批量执行面板（进度、取消、逐用例状态）。
- 计划维度的报告（含重试与失败归因）。
- CLI `--plan` + JUnit 文件。
- iframe 用例回放通过（修复 frame 上下文后的直接体验）。

**垂直切片**

- DB：`suites / suite_items / plans / plan_items`；`runs` 增加 `plan_id / attempt`。
- Main：批量执行服务、计划仓储、进度 IPC、取消。
- Runner：批量执行、重试/超时/失败策略；frame 路径定位。
- Renderer：测试计划页、用例多选/批量加入、执行面板、计划报告。
- CLI：`atp run --plan <id> --junit <path> --headless`，退出码。

**与现有功能的联动**

- 用例树支持多选与批量操作；保存用例后可「加入计划」。
- 执行中 AppBar 录制/回放状态区显示「计划执行中」；状态栏显示进度。
- 报告页新增「按计划」筛选；执行记录关联计划与重试。
- 空态：无计划、无套件、用例为空；错误：用例不存在、执行失败；禁用：执行中禁止编辑计划。

**UI/UX 一致性**

- 复用现有 AppBar / 侧栏 / 分段标签 / 卡片 / Toast / 空状态。
- 进度条复用录制/回放条样式；重试标记用现有 chip 体系。
- 新页面沿用 288 / 404 栏宽与 52px 工具条节奏。

**验收**

- 10 条用例计划一键执行；失败用例可重跑；取消生效。
- JUnit 可被 CI 消费；iframe 用例回放通过。
- 用户不看文档也能从「用例 → 套件 → 计划 → 执行 → 报告」走通。

**不做**

- 并行、定时、通知、服务端。

### L2 · 场景覆盖（L）

**谁 / 场景 / 之前 / 之后**

- 测试同学面对企业后台 / 弹窗 / 上传等页面；之前这些交互录不了，之后可以完整录制回放。

**体验脚本**

1. 录制一个含 hover、双击、右键、上传文件、弹出新窗口的页面。
2. 右栏实时出现对应步骤（动作 chip 明确区分），保存后在步骤编辑器可调整参数。
3. 回放时动作在中栏可见地执行；报告展示新动作与文件证据。
4. 元素库页面能看到元素所属 frame、被哪些用例引用。

**锚定交付物**

- 新动作：hover / 双击 / 右键 / 组合键 / 上传 / 下载 / 弹窗多标签 / 容器滚动。
- 录制、实时预览、步骤编辑、回放、报告全链路可见。
- 全局元素库页：搜索、引用数、所属 frame、合并/修复入口。
- iframe frame 路径在元素编辑器中可见。

**垂直切片**

- Recorder：新事件采集、弹窗注入、下载事件。
- Model/Runner：新动作 schema 与执行。
- Main：多 webContents/page 管理、文件路径与证据。
- Renderer：动作 chip、编辑器字段、报告标签、元素库页。
- DB：元素 frame 路径、引用关系查询。

**联动 / UX**

- 动作选择器按「基础 / 交互 / 文件 / 窗口」分组；新动作沿用现有颜色体系。
- 元素库从右栏标签升级为可独立访问的页面，但保留右栏快捷入口。
- 报告沿用步骤卡片结构，新增文件/窗口信息的展示位。

**验收**

- 含弹窗、上传、hover、右键的演示页可录制并回放。
- 元素库能回答「这个元素在哪、被谁用」。

**不做**

- 真机、跨浏览器、视觉断言。

### L3 · 断言与证据（M）

**谁 / 场景 / 之前 / 之后**

- 测试同学需要验证接口与前端行为；之前只能断言页面文本，之后可以同时断言网络、控制台，并用 Trace 定位失败。

**体验脚本**

1. 在步骤编辑器新增断言，类型分组里出现「网络」「控制台」。
2. 执行后报告详情出现「步骤 / 网络 / 控制台 / Trace」分段。
3. 失败时点「打开 Trace」直接定位到出错的请求或元素。
4. 软断言失败不中断，报告汇总所有失败点。

**锚定交付物**

- 网络断言、控制台断言、软断言。
- Trace/HAR/控制台日志证据与查看入口。
- 报告详情新增证据分段。

**垂直切片**

- Runner：事件监听、断言轮询、Trace 采集、软断言汇总。
- Main：证据文件归档、协议读取。
- Renderer：断言编辑器分组、报告分段、Trace 打开。
- CLI：失败输出包含证据路径。

**联动 / UX**

- 断言编辑器沿用现有分组下拉，不新增独立页面。
- 报告沿用现有分段标签，新增证据标签不改变整体结构。
- 加载/失败/空证据都有明确提示。

**验收**

- 一条用例联合断言 UI + 接口 + 控制台；失败可用 Trace 定位。

**不做**

- 视觉回归、可访问性、性能预算（放 L5）。

### L4 · 数据与环境（M）

**谁 / 场景 / 之前 / 之后**

- 测试同学需要在多环境、多组数据下跑同一用例；之前地址/账号写死，之后可以切换环境、导入数据集、准备/清理数据。

**体验脚本**

1. 新增「环境与变量」页：创建 dev/staging，填写 baseUrl 与变量，密钥输入后显示为掩码。
2. 用例中使用 `${baseUrl}` / `${secret.password}`；计划执行时选择环境。
3. 导入 CSV 数据集，计划选择「按数据集循环」；报告按数据集分组。
4. 用例配置 setup/teardown（HTTP 或 UI 步骤），执行前后自动运行。

**锚定交付物**

- 环境与变量页、密钥安全存储（OS Keychain）。
- 数据集导入、循环执行、报告分组。
- setup/teardown 编辑与执行。
- 登录态复用（storageState）。

**垂直切片**

- DB：environments / variables / secrets / datasets。
- Main：safeStorage 加解密、作用域解析、计划注入。
- Runner：数据集循环、setup/teardown、HTTP 动作、storageState。
- Renderer：环境页、数据集向导、计划配置、报告分组。

**联动 / UX**

- 变量编辑器升级为「作用域视图」，与现有用例变量弹窗保持一致。
- 计划执行页展示当前环境与数据集进度。
- 密钥字段统一掩码与「显示」权限（本地确认）。

**验收**

- 同一用例在 dev/staging 切换执行；20 组数据一次执行并分组；密钥不出现在日志/报告。

### L5 · 度量与规模化（L）

**谁 / 场景 / 之前 / 之后**

- 测试负责人需要看质量趋势与 flaky；之前只有单次记录，之后有本地看板、运行对比、定时与通知。

**体验脚本**

1. 工作台出现「质量概览」：近 7 天通过率、失败 Top、flaky 用例。
2. 两次执行可对比步骤级差异。
3. 定时任务在应用内/系统 cron 配置，失败后本地通知/飞书 Webhook。
4. 视觉回归 / 可访问性 / 性能断言在报告中可见。
5. 用例版本、导入导出、定位器健康度可操作。

**锚定交付物**

- 本地看板、运行对比、flaky 标记。
- 定时配置页 + Webhook 通知。
- 视觉/可访问性/性能断言与证据。
- 用例版本、导入导出、定位器健康度。

**垂直切片**

- DB：版本、度量查询、定时配置。
- Runner：视觉 diff、axe、性能采集、跨浏览器。
- Main：定时/通知、导入导出。
- Renderer：看板、对比、版本、设置。
- CLI：定时/CI 场景完善。

**验收**

- 本地回归可日常运行；质量趋势与失败责任可追溯。

**不做**

- 服务端、多用户、云端执行（本地闭环稳定后再评估）。

## 6. 本地技术实现要点（技术栈不变）

| 主题 | 做法 |
|---|---|
| 计划/套件 | SQLite 新表 + 主进程批量执行器；UI 增加「测试计划」页 |
| 批量与重试 | 复用 `runCaseOnPage`；外层层重试与超时；run/attempt 落库 |
| CLI | `packages/runner/cli` 增加 `--plan`、`--junit`；读本地 SQLite（只读）或计划 JSON 包 |
| iframe | 元素增加 `framePath`（索引链/URL）；回放用 `page.frames()` 定位后再找元素 |
| 弹窗/多标签 | 录制：`setWindowOpenHandler` + 新 webContents 注入；回放：`page.on('popup')` + page 映射 |
| 上传/下载 | 上传记录相对路径（测试数据目录）；下载用 Playwright download 事件落证据 |
| 网络/控制台 | 执行期事件监听；断言轮询；证据落本地目录 |
| Trace | `context.tracing`；文件落 `runs/<id>/trace.zip` |
| 视觉 | 截图 + `pixelmatch`；基线按环境/设备存本地 |
| 密钥 | `safeStorage.encryptString`；只存密文；日志脱敏 |
| 定时 | 系统 cron/launchd 调 CLI；应用内定时作为辅助 |
| 并行（可选） | 多浏览器上下文并发；按 CPU/内存限流 |

**不引入的东西**：服务端、PostgreSQL、Redis、对象存储、Worker 池、多用户/权限、SSO。

## 7. 首个迭代（2 周）

**主题：L1 的第一刀——「用例 → 套件 → 计划 → 批量执行 → 报告」本地闭环**

**谁 / 场景 / 之前 / 之后**

- 测试同学，本地做登录回归；之前一条条跑，之后多选用例建套件/计划，一键批量执行并看计划报告。

**体验脚本（必须能完整演示）**

1. 左树多选 3 条用例 → 「加入套件」→ 新建「登录回归」。
2. 顶部出现「测试计划」→ 新建计划，选「登录回归」，重试 1 次、失败继续。
3. 点「执行」→ 右栏计划执行面板显示逐用例状态、步骤进度、重试标记。
4. 执行完成 → 报告切到计划视图，展示失败步骤与截图。
5. 计划详情复制 CLI 命令 / 导出 JUnit。

**锚定交付物**

- 「测试计划」导航、套件/计划列表与编辑、批量执行面板、计划报告、CLI/JUnit。
- iframe 用例回放通过（frame 上下文修复）。

**垂直切片（一次交付，不允许只做一段）**

- DB：`suites / suite_items / plans / plan_items`；`runs` 增加 `plan_id / attempt`。
- Main：计划仓储、批量执行服务、进度 IPC、取消。
- Runner：批量执行、重试/超时/失败策略、frame 路径定位。
- Renderer：测试计划页、用例多选/批量加入、执行面板、计划报告。
- CLI：`--plan <id> --junit <path> --headless` + 退出码。
- E2E：10 条用例计划 + 失败重试 + JUnit。

**联动与 UX 检查**

- 用例树多选工具栏、保存后「加入计划」入口。
- AppBar/状态栏在执行计划时显示进度；报告按计划筛选。
- 新页面沿用现有布局/组件/token；空态、加载、失败、禁用、暗色模式逐一走查。
- 失败提示与现有 Toast/报告风格一致。

**验收（用户视角）**

- 不看文档能走通「多选用例 → 建套件 → 建计划 → 执行 → 看报告」。
- 失败用例可重跑；取消生效；CI 拿到 JUnit。
- iframe 用例回放通过。

**不做**

- 并行、定时、通知、环境/密钥（放后续里程碑）。

## 8. 需要你确认的三件事

1. **首批优先场景**：实际业务里最常被测的是哪类页面？（iframe 企业后台 / 弹窗多标签 / 上传下载 / 登录鉴权）
2. **CI 形态**：主要用 GitHub Actions、GitLab CI 还是 Jenkins？决定 CLI/JUnit 示例与目录约定。
3. **测试数据**：是否有一个固定的测试数据目录/账号体系？决定上传文件与登录态复用的设计。
