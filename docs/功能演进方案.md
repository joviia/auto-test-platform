# 本地优先的功能演进方案

> 边界：**技术栈不变、单机本地、不做服务端、不做多用户/云**。
> 目标：先把本地功能做完整，覆盖软件工程对测试的基本要求；云化以后再说。
> 版本：v2 · 2026-10-17

---

## 0. 结论先行

- **现在的问题不是架构，是功能覆盖太窄**：一次只能跑一条用例、录制动作少、断言薄、没有测试计划/套件、没有数据与环境管理。
- **下一步主线**：把「单条用例录制回放」升级为「本地可执行的测试工程闭环」。
- **优先级**：
  1. 测试执行闭环（套件/计划/批量/重试/报告）——最缺
  2. 场景覆盖（弹窗多标签、hover/双击/右键、上传下载、复杂控件）
  3. 断言与证据（网络/控制台/软断言/Trace）
  4. 数据与环境（变量作用域、环境、密钥、数据集、setup/teardown）
  5. 维护与度量（全局元素库、版本、趋势、flaky）
- **技术栈不变**：Electron + WebContentsView + CDP + Playwright + SQLite。

## 1. 现状盘点

### 1.1 已具备

| 域 | 能力 |
|---|---|
| 录制 | 点击 / 输入 / 下拉 / 按键 / 滚动 / 拖拽（含滑块）/ 断言拾取；同域与跨域 iframe 采集 |
| 定位 | testId → role+名称 → text → CSS 多候选链；逐层回退与命中记录 |
| 用例 | 项目 / 模块 / 用例树；步骤拖拽排序、复制、内联编辑；⌘S |
| 断言 | 元素状态 8 类、数量、文本 3 类、值 2 类、属性、CSS、页面级 URL/标题/页面文本 |
| 参数化 | 用例变量 `${VAR}`、步骤条件（跳过） |
| 回放 | 中栏 CDP 嵌入（截图）/ 独立窗口（视频）；进度与停止；失败即停 + 候选归因 |
| 设备 | Desktop / Laptop / Tablet / iPhone / Android，横竖屏与缩放 |
| 证据 | 步骤截图、独立窗口视频、执行记录、报告页 |
| 工程 | CLI 单用例回放、E2E、单测、明暗主题、Toast/确认框 |

### 1.2 关键缺口（按影响排序）

| 缺口 | 影响 |
|---|---|
| **iframe 回放没有 frame 上下文** | 录制能进 iframe，回放时在主文档找元素会失败 |
| 只能单条用例执行 | 没有套件/计划/批量，做不了回归 |
| 动作覆盖窄 | 弹窗/多标签、hover、双击、右键、上传/下载、组合键、复杂控件都录不了 |
| 断言薄 | 没有网络、控制台、视觉、可访问性、性能断言；没有软断言 |
| 没有测试数据/环境 | 地址与账号写死在用例里；没有数据集、setup/teardown |
| 没有测试资产治理 | 元素库只能看当前用例；没有版本、导入导出、批量操作 |
| 没有度量 | 只有执行列表，没有趋势、flaky、失败分派 |
| CI 能力弱 | CLI 只能跑单条 case JSON，没有批量与 JUnit |

### 1.3 现有架构的优点（保持不变）

- 用例是结构化 JSON，适合本地演进，也天然兼容未来的云化。
- `packages/recorder` / `packages/runner` 零 Electron 依赖，CLI 可以直接复用。
- 多候选定位器 + 步骤级证据 + 失败归因，已经是可诊断的底座。
- 技术栈不需要调整：本地 SQLite 足够支撑测试计划、环境、执行记录与趋势。

## 4. 功能域与做法

### 4.1 测试执行闭环（L1，最优先）

**目标**：从「单条用例」升级为「套件 → 计划 → 批量执行 → 报告」。

- **套件（Suite）**：按功能域/模块组织用例，支持拖拽排序与批量加入。
- **测试计划（Plan）**：套件 + 执行策略（重试次数、超时、失败继续/即停）+ 环境（L4 前可先只用默认环境）。
- **本地批量执行**：主进程顺序执行计划内用例；每条用例独立上下文；实时进度；可取消。
- **重试与超时**：用例级重试（默认 0，可配 1~3）；单步/用例超时；重试记录独立保存。
- **失败策略**：失败即停 / 继续执行（收集全貌）；报告标注。
- **执行记录**：run 关联 plan/suite/case；保留每次尝试。
- **CLI 批量**：`atp run --plan <id> [--junit report.xml] [--headless]`；退出码；可被 CI 调用。
- **JUnit XML**：每条用例一个 testcase，失败附步骤与断言信息。
- **标签/优先级**：`smoke` / `regression` / `P0~P2`；计划可按标签筛选。
- **iframe 回放修复**：元素记录 frame 路径，回放先定位 frame。

**怎么做**

- SQLite 新增：`suites`、`suite_items`、`plans`、`plan_items`、`plan_runs`（或复用 runs 增加 plan_id）。
- 批量执行器：复用 `runCaseOnPage`，在本地起多个 Playwright 浏览器（先串行，L5 再并行）。
- CLI 读取本地 DB 的计划（只读），避免依赖桌面 UI。
- 重试：包一层 `runCaseOnPage`，失败后按策略重跑并记录 attempt。
- JUnit：新增 `packages/runner/src/junit.ts`，纯函数便于测试。

**验收**

- 一个 50 条用例的计划可一键执行，失败用例可重跑。
- 执行结束生成 JUnit，CI 可直接消费。
- iframe 用例回放通过。

### 4.2 录制与动作（L2）

**目标**：覆盖企业 Web 常见交互。

- 弹窗/新标签：录制 `open_tab / switch_tab / close_tab`；受控视图允许 `window.open` 并注入采集器。
- hover、双击、右键：新增动作；采集对应 DOM 事件。
- 键盘组合键：录制 `ctrl/meta/alt/shift + key`，回放用 `keyboard.press`。
- 文件上传：记录文件输入；本机测试数据目录保存文件路径，回放 `setInputFiles`。
- 文件下载：监听下载事件，证据落盘；断言文件存在/大小。
- 滚动容器：不仅窗口滚动，也支持可滚动元素。
- 复杂控件：日期选择器、富文本、下拉树、穿梭框——按「录制动作 + 组件策略」扩展，不引入组件库耦合。
- Shadow DOM：open shadow root 优先 role/text；closed 需录制期建立映射或手动修正。
- 元素库全局管理：跨用例搜索、合并、引用影响分析。

**验收**

- 一个含弹窗、上传、hover、右键的页面可完整录制并回放。
- 元素库能看出某元素被哪些用例引用。

### 4.3 断言与证据（L3）

**目标**：从「页面可见」扩展到「系统行为」。

| 类别 | 内容 |
|---|---|
| 网络 | 请求发生、状态码、响应体 JSONPath、响应时间 |
| 控制台 | 无 error、指定日志出现 |
| 软断言 | 失败不中断，汇总展示 |
| 视觉（L5） | 元素/整页截图基线对比、差异图、阈值 |
| 可访问性（L5） | axe 规则集与严重级别 |
| 性能（L5） | 首屏/接口耗时预算 |

**证据**

- Playwright Trace（失败用例默认开启，成功可选）。
- HAR / 网络日志、控制台日志。
- 嵌入回放可选视频（后续用 CDP screencast，不依赖 ffmpeg）。
- 报告页可直接打开 Trace、查看网络与控制台。

**怎么做**

- 网络：执行期监听 `page.on('request/response')`，断言按轮询匹配。
- 控制台：监听 `console` 与 `pageerror`。
- 软断言：步骤结果增加 `softFailed`，继续执行，最终汇总。
- Trace：`context.tracing.start/stop`，文件落证据目录。
- 视觉：截图 + `pixelmatch`（本地计算），基线存本地目录。

**验收**

- 一条用例可同时断言 UI 文本、接口 200、控制台无 error；失败报告分别列出。
- 失败用例报告可直接打开 Trace。

### 4.4 数据、环境与密钥（L4）

**目标**：同一套用例在不同环境/数据下运行。

- **环境（Environment）**：名称、baseUrl、浏览器/视口、默认超时、变量集合。
- **变量作用域**：全局 < 项目 < 环境 < 计划 < 用例；同名覆盖。
- **密钥**：Electron `safeStorage`（macOS Keychain / Windows Credential Manager）加密；日志与报告脱敏。
- **数据集**：CSV/JSON 导入；用例循环执行，结果按数据集聚合。
- **setup / teardown**：前置/后置步骤（UI 或 HTTP）；失败不执行后置时给出提示。
- **HTTP 动作**：为数据准备/清理、API 断言、混合测试提供基础。
- **登录态复用**：Playwright `storageState` 保存与复用。

**验收**

- 同一用例切换 dev/staging 两套环境无需修改。
- 20 组数据集一次执行，报告分组展示。
- 密钥不出现在用例 JSON、日志、报告中。

### 4.5 报告与度量（L5）

- 趋势：通过率、耗时、失败 Top N、环境对比。
- Flaky 识别：同一用例多次执行结果不一致，自动标记。
- 运行对比：两次执行的步骤级差异。
- 失败分派：责任人、备注、状态（待修/已修/忽略）。
- 分享：导出 HTML/JUnit；本地报告文件可直接发人。

### 4.6 CI 与定时（L5）

- CLI 批量与 JUnit（L1 已有基础）。
- 退出码、日志、artifacts 目录约定。
- GitHub Actions / GitLab CI 示例。
- 定时：优先使用系统 cron/launchd 调 CLI；应用内定时可作为辅助（应用需常开）。
- 通知：本地 Webhook / 飞书机器人（失败摘要 + 报告路径）。

### 4.7 可维护性与资产治理（L5）

- 用例版本：保存快照，可回滚；执行记录关联版本。
- 导入/导出：平台 JSON 包（用例 + 元素 + 变量 + 数据集）。
- 定位器健康度：统计候选命中层级；长期命中低层的元素给出修复建议。
- 全局元素库：合并重复元素、批量修复定位器。

## 6. 本地技术实现要点（技术栈不变）

| 主题 | 做法 |
|---|---|
| 计划/套件 | SQLite 新表 + 主进程批量执行器；UI 增加「测试计划」页 |
| 批量与重试 | 复用 `runCaseOnPage`；外层层重试与超时；run/attempt 落库 |
| CLI | `packages/runner/cli` 增加 `--plan`、`--junit`；读本地 SQLite（只读）或计划 JSON 包 |
| iframe | 元素增加 `framePath`（索引链/URL）；回放用 `page.frames()` 定位后再找元素 |
| 弹窗/多标签 | 录制：`setWindowOpenHandler` + 新 webContents 注入；回放：`page.on('popup')` + page 映射 |
| 上传/下载 | 上传记录相对路径（测试数据目录）；下载用 Playwright download 事件落证据 |
| 网络/控制台 | 执行期事件监听；断言轮询；证据落本地目录 |
| Trace | `context.tracing`；文件落 `runs/<id>/trace.zip` |
| 视觉 | 截图 + `pixelmatch`；基线按环境/设备存本地 |
| 密钥 | `safeStorage.encryptString`；只存密文；日志脱敏 |
| 定时 | 系统 cron/launchd 调 CLI；应用内定时作为辅助 |
| 并行（可选） | 多浏览器上下文并发；按 CPU/内存限流 |

**不引入的东西**：服务端、PostgreSQL、Redis、对象存储、Worker 池、多用户/权限、SSO。

## 7. 首个迭代（2 周）

**主题：测试执行闭环（L1 的第一刀）**

1. SQLite 表：`suites / suite_items / plans / plan_items`；执行记录增加 `plan_id`、`attempt`。
2. 主进程批量执行器：顺序跑计划；实时进度事件；取消。
3. 重试与超时：计划级配置，run 记录每次尝试。
4. UI：新增「测试计划」页；用例多选加入套件/计划；计划执行与进度。
5. CLI：`--plan <id>`、`--junit <path>`、`--headless`；退出码。
6. **iframe 回放修复**：元素记录 frame 路径，回放按 frame 定位。
7. E2E：10 条用例计划执行 + 失败重试 + JUnit 生成。

**验收**：试点同学在本地创建套件/计划，一键跑 10 条用例，失败可重跑，CI 拿到 JUnit。

## 8. 需要你确认的三件事

1. **首批优先场景**：实际业务里最常被测的是哪类页面？（iframe 企业后台 / 弹窗多标签 / 上传下载 / 登录鉴权）
2. **CI 形态**：主要用 GitHub Actions、GitLab CI 还是 Jenkins？决定 CLI/JUnit 示例与目录约定。
3. **测试数据**：是否有一个固定的测试数据目录/账号体系？决定上传文件与登录态复用的设计。

## 9. 明确不做（本轮）

- 服务端、Web 管理台、多用户/权限、SSO
- 云执行、分布式 Worker、对象存储
- 跨浏览器与真机（放到 L5 之后评估）
- 云化之后再谈的开放 API/SDK、插件市场
